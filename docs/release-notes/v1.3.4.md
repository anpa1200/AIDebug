# AIDebug v1.3.4 Release Notes

## Hash-indexed analysis history

AIDebug now treats SHA-256 as the stable identity of an analyzed sample. When
identical bytes are opened from the same or a different path, AIDebug announces
the matching local sessions and restores compatible stored function analyses
without repeating the remote-AI request.

The original sessions remain immutable historical records. A new run receives
its own session ID, while the main GUI's **History** tab shows prior session
metadata, evidence counts, risk counts, and saved function summaries. Press
`Ctrl+H` to open it.

## File-or-hash lookup

Query retained evidence without launching a new analysis:

```bash
aidebug --history /path/to/sample.exe
aidebug --history 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

The command hashes an existing file or accepts a complete SHA-256. It lists
every matching session and stored AI function finding, then provides the exact
`--session ... --json-export` command for exporting all persisted fields.

## Session lifecycle metadata

SQLite schema version 7 adds the analysis mode, analyzer identity, lifecycle
status, and completion timestamp. Existing databases are upgraded with an
additive migration, and a SHA-256 index makes repeat-sample lookup efficient.

The default database remains private local state at
`$XDG_STATE_HOME/aidebug/traces.db` (normally
`~/.local/state/aidebug/traces.db`). It can contain sensitive case evidence and
should be protected accordingly.

## Expanded real learning corpus

Learning Mode now contains 53 independently compiled C cases. Six new lessons
cover integer negation, masked-bit testing, variable rotate-right, post-tested
loops, binary search, and in-place buffer reversal. As with the existing
lessons, AIDebug compiles only the selected source file, never executes the
temporary ELF, displays its real instructions, and asks Ghidra to reconstruct
the pseudo-code.
