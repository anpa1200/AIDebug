# AIDebug v3.1.0 Release Notes

AIDebug 3.1 adds a complete String Intelligence workflow for deterministic,
occurrence-aware extraction and analyst-controlled AI triage. The feature is
available in the original terminal interface and through a dedicated CLI/JSON
path without executing the inspected artifact.

## Whole-file string evidence

AIDebug scans every byte of the size-bounded artifact for selected ASCII,
UTF-8, UTF-16LE, and UTF-16BE strings. Records preserve stable evidence IDs,
file offsets, mapped addresses where available, encoding, original lengths,
duplicate occurrences, section context, and bounded previews. Retention is
capped at 25,000 records and 4,096 stored characters per value; exact candidate
and omission counts make either cap visible instead of silently claiming full
inventory coverage. Per-record DLL/API annotations are capped at 32 entities
and 4,096 description characters, with explicit reasons when candidates are
omitted.

## Smart deterministic classification

String detection is multi-label and ranks evidence without treating presence
as proof of execution or maliciousness. Categories cover DLLs, imported and
candidate APIs, commands, PowerShell, URLs, domains, IPv4 and IPv6 addresses,
registry keys, Windows and POSIX paths, named pipes, hashes, credentials,
persistence clues, anti-analysis text, and other analyst-relevant forms.
Known DLLs and APIs receive concise neutral descriptions from packaged local
data; unknown names remain explicitly unverified.

Domains are IDNA-normalized and checked against a packaged IANA root-zone
snapshot without DNS requests. IP matching validates complete maximal tokens,
including balanced bracket/port and IPv6-zone syntax, rather than accepting a
valid substring inside a malformed value. Configuration recognition uses a
conservative full-line environment/INI/YAML grammar so short binary fragments
are left as ordinary text. Related labels such as `ip_address` plus `ipv6`, or
`url` plus `domain`, count as one evidence family for score and confidence.

## Terminal workspace and CLI export

Press `S` in the main interface or start with `--strings` to open the paginated
String Intelligence workspace. Analysts can filter by length, encoding,
category, or text, sort columns, inspect occurrences and explanations, and
review deterministic and AI findings separately. `--strings --no-tui` provides
the same inventory for automation, while `--strings-output` writes canonical
owner-only JSON atomically without creating an analysis database or requiring
function discovery.

## Evidence-grounded AI review

Whole-inventory AI triage is never automatic. After explicit privacy and cost
acknowledgement, every retained string is sent in deterministic bounded chunks
with attacker-controlled evidence isolated from instructions. Responses must
account for every supplied ID and pass strict schema, enum, reference, entity,
and type-specific IOC validation. Failures, unattempted chunks, extraction
limits, and incomplete coverage remain visible and force an unknown aggregate
assessment rather than a safe conclusion.
Closing the String Intelligence workspace requests cooperative cancellation:
an in-flight request may finish, but no subsequent chunk or reducer request is
started, and any partial result remains explicitly unknown.

Local Ollama endpoints are recognized only from IP-literal HTTP(S) loopback URLs,
and their HTTP client ignores proxy environment variables and refuses
redirects. Unix-socket URLs are rejected until AIDebug has a dedicated Unix
transport. Non-loopback endpoints are treated as remote evidence transfers and
require the same explicit acknowledgement as other remote providers.

## Validation

The 3.1 release gate covers the extractor, smart classification, hostile
strings, chunk and reducer validation, UI interactions, CLI privacy behavior,
streaming JSON security, release metadata, documentation, and packaged data.
Wheel and source-distribution checks require the local DLL/API description
database, and the installed-wheel smoke test exercises String Intelligence
directly.
