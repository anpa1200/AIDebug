# AIDebug v1.2.0 Release Notes

Release date: 2026-08-08

## Summary

AIDebug v1.2.0 expands static triage from PE binaries to ELF binaries and
single-file C source, and replaces the earlier heuristic pseudo-source renderer
with genuine Ghidra headless decompilation. The output remains reconstructed
C-like code rather than recovered original source and must be reviewed against
the disassembly and observed behavior.

## What Changed

- Added bounded Ghidra headless decompilation for PE, ELF, and temporary ELF
  artifacts compiled from C source.
- Added image-base normalization so Ghidra and AIDebug addresses remain aligned
  for PE images and position-independent ELF binaries.
- Removed the misleading pseudo-C/C++ register-translation fallback and its
  `--decompile cpp` mode.
- Added bounded `.c` source preparation using an ELF compiler inside a
  Bubblewrap filesystem sandbox; the compiled artifact is never executed.
- Added actionable Ubuntu AppArmor diagnostics for Bubblewrap UID-map denial.
- Propagated decompiler backend, language, and reconstruction warnings through
  the CLI, TUI, SQLite database, HTML report, and JSON export.
- Expanded ELF symbol-based function discovery and persisted source/compiled
  artifact provenance.
- Hardened static/dynamic analysis bounds, database migrations, reports,
  optional AI paths, packaging checks, and release automation.

## Installation

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install ".[all]"
```

Ghidra is an optional system dependency for `--decompile`. C-source analysis
requires Bubblewrap and an ELF-capable C compiler. On Ubuntu 24.04, install an
AppArmor profile for Bubblewrap instead of disabling the system-wide
unprivileged-user-namespace restriction.

## Verification

The release gate validates metadata, documentation, Ruff, pytest, Bandit,
dependency audits, JavaScript syntax, wheel/sdist contents, Twine metadata,
optional Frida imports, safe ELF analysis, and offline report generation.

```bash
./scripts/release-readiness.sh
```

The Ghidra integration was additionally smoke-tested against benign x86-64 PE
and ELF artifacts, including address reconstruction at `0x140001190`.

## Known Limits

- Decompiler output is reconstructed C-like code, not original source.
- Function discovery remains bounded and can miss indirect, packed, stripped,
  overlaid, or unreachable code.
- C-source analysis supports one translation unit with system headers; it does
  not yet support project-local include trees or multi-file builds.
- Ghidra, Bubblewrap, compilers, remote AI, and Frida remain optional external
  dependencies with platform-specific installation requirements.
