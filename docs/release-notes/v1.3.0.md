# AIDebug v1.3.0 Release Notes

Release date: 2026-08-08

## Summary

AIDebug v1.3.0 adds full-program Ghidra reconstruction, an assembly-grounded
LLM cross-check, a true analyst-controlled local ELF debugger, and a local
44-lesson reverse-engineering curriculum.

## What Changed

- `--decompile-all FILE.c` writes every discovered function with source hash,
  backend, address, and non-original-source provenance.
- Remote AI analysis cross-checks available Ghidra code against the bounded
  disassembly and related evidence, returning status, confidence, concrete
  findings, and optional corrected pseudo-code.
- `--mode debug` uses GDB/MI for breakpoints, continue, instruction step/next,
  finish, register inspection and deltas, nearby disassembly, and function
  input/output candidates.
- `--learn` provides 44 searchable lessons covering instruction families,
  high-level structure recovery, Windows behavior, IAT thunks, and PEB access.
- Reports, JSON, the TUI, storage, packaging metadata, and safety documentation
  include the new cross-check and debugging boundaries.

## Safety And Accuracy

Full decompilation remains bounded by function discovery and is not recovered
source. LLM review is not semantic-equivalence proof. Active debug executes the
selected ELF and must be used only in an authorized, isolated lab. Learning
mode is bundled, local-only content and executes no sample.

## Installation

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install ".[all]"
```

Ghidra is required for decompilation. GDB is required for active local ELF
debugging. Both are system dependencies.

## Verification

```bash
./scripts/release-readiness.sh
```

The release suite covers the 44-lesson catalog, combined reconstruction output,
strict AI review schema, GDB/MI state parsing, CLI validation, reports, storage,
packaging, and existing static/dynamic functionality. A benign compiled C
fixture is also manually exercised through a real breakpoint/step/finish flow.
